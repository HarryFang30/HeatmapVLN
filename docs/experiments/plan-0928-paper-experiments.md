## 3. 任务 2：实时性测试

**需求**：加几个 timer 测实时性。

**现状**（查代码所得）：
- **代码里没有任何计时。** 唯一的数字是部署文档里的"每卡 1–1.3 s 一步"。
  - 这个数包含 CPU 软件渲染和在线建图，不能当模型延迟来报。
- **部署是同步的。**
  - 每次规划都在同一个 RPC 里完成：先由慢系统生成（最多 128 个 token；输出"↓"时还有第二轮），再由快系统出轨迹。
  - 一次最多执行 4 个动作，然后重新规划。
  - 没有独立运行的快系统循环。

**计划**：
- 在服务端、客户端和里程计服务里加 `torch.cuda.synchronize()` + `perf_counter`，分段计时：
  1. 里程计：每步的帧写入、每次规划的位姿查询
  2. 慢系统生成（第一轮 / 第二轮分开计）
  3. 历史认知头 + 注入
  4. 快系统（S=32 条采样、M=10 步去噪）
  5. 轨迹转动作
  6. 一次规划的端到端时间，再折算到每个动作
  - 另报显存峰值。仿真渲染单独一栏，不计入模型延迟。
- **计时不能改变行为。** 加完后按 EXP-19 冒烟的做法，与金丝雀逐调用比对。
- **样本量**：约 100 集就够；也可以直接挂在任务 1 的 A0 全量评测上，不额外占卡。

**D5 要讨论的：**
- **报什么硬件？** 能测的只有 4090。机器人上用什么算力？
- **要不要报相对 native 的额外开销？** 即历史认知头 + 注入 + 里程计比 native 多花多少时间。
- **里程计那一行怎么称呼？**
  - 正文 3.3 已经隐去了位姿，但延迟表不能漏掉里程计的耗时，它可能是大头之一。
  - 措辞要和附录 B 一致："相对位姿由慢系统顺序读入 RGB 增量估计"。
- **"异步"要不要改口？** 正文写的是"慢快异步"，实测是同步。表里只能写实测，所以要么正文同步改口径，要么在表注里说明。

## 6. 任务 5：实际部署接口文档

**需求**：给出实际部署的接口（输入 RGB 图像，输出动作），把接口写清楚，写成文档。

**现状**（查代码所得）：
- **只用 RGB。** 不需要深度，也不需要真值位姿；位姿由里程计从 RGB 序列在线估计。
- **但不止一张图：**
  - **每走一步**：一张前视 RGB 送给里程计。仿真里的相机参数是 640×480、HFOV 79°、离地 1.25 m、水平安装。
  - **每次规划**：需要四样东西。
    - 当前前视 RGB。
    - 一张**下倾 30°** 的 RGB。慢系统在这张图上给像素目标，快系统也用它；4090 上所有关键时刻的决策图都是这张。
    - 最多 8 张历史前视帧，由客户端从已走过的帧里均匀挑选。
    - 指令。
  - **前 20 步**里程计还在建图，这段只走原生路径，不用历史认知。
- **输出**：
  - 每次规划最多返回 4 个离散动作：停止 / 前进 0.25 m / 左转 15° / 右转 15°，以及下视。
  - 执行完这几个动作，或遇到停止，再重新规划。
  - 连续路点在内部有，但现在没有返回。
- **现在的协议是为仿真评测写的 gRPC：**
  - 还要求传右 / 后 / 左三张实际没用到的图。
  - 要传场景号和集号，用来定随机种子。
  - 历史帧缓存、动作队列、里程计会话都放在 Habitat 客户端里。
  - 没有"一个函数进 RGB、出动作"的入口。

**方案**：
- 写一个与仿真无关的封装：`NavAgent.reset(instruction)`、`NavAgent.step(front_rgb, lookdown_rgb=None) -> actions`。
  - 内部管理历史帧、动作队列、里程计会话和预热。

**D11 要讨论的：**

## 7. 任务 6：R2R 再提 1–2 个点

**需求**：SR 做到 64–65，也就是再提一两个点。

**现状**：

  - 桥这条线在结构上改不了"去哪"。
- **不重训能调的只有推理设置**，都没测过：
  - §5 里快系统的那几个参数；
  - 纯追踪的前瞻距离、终点容差、每次执行的动作数。

**怎么做才站得住：**
- **在 val_seen 上调参。** 4090 上有这个划分，778 集。

**D12 要讨论的：**

折算：2 张卡不间断跑约 16–19 天，4 张卡约 8–10 天。此刻空卡是 0 张。

**可能的提速**（都要先验证不改变行为）：
- 客户端每一步都在渲染右 / 后 / 左三个视角，但部署配置根本不用它们。改成不渲染，可能会明显快一些（渲染是 CPU 软件渲染）。
- 把里程计放到另一张卡上，就能用上显存只剩一半的卡。

**建议顺序：**
1. **马上能做、不占 GPU**：
   - 图 A / 图 B（先用 4090 上现有的 5 集）。
   - 加计时代码。
   - 部署接口的封装和文档。
2. **有空卡后的第一件事**：跑 A0 种子 42 全量，并带上计时。这一次同时产出 4090 基线和实时性表。
3. **之后**：A1 → 消融其余臂 → 提点（val_seen）→ 敏感性，每项开跑前先把判据写进台账。
