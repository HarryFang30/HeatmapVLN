## 2. D1 — 靶子存在，但比预注册假设的弱一半

### 2.1 两处必须先讲清楚的测量问题

**问题一：1274 个状态的方向根本没有定义，却被算进了"非前视"。**
`oracle_outside_front_frac` 的定义是"oracle 未来位姿里**第一个离开当前位置 ≥0.5 m 的点**
落在非 front 视角**或四视角都不可见**的比例"。实现把"**根本不存在这样一个点**"
（oracle 在整个未来窗口里位移都 < 0.5 m）和"存在但四视角不可见"折进了同一个桶。
实测这两类分别是 **1274** 个和 **18** 个——也就是说 JSON 里 6.18% 的"invisible"
几乎全是前者。

这 1274 个状态**全部**落在 `necessary_backtrack` 标签里（5340 − 4066 = 1274，精确相等）：
oracle 在**原地转身**，位移当然不到 0.5 m。语义上它们确实是恢复状态，
但"0.5 m 位移后的方向"这个指标**在它们身上没有定义**，把它们记成"非前视"等于
用未测量的样本给假设投票。

因此本报告以**只在有定义的 19629 个状态上**算的 **0.2569** 为主读数，
如实现口径的 0.3022 作为对照列出。两个口径的判定都是"没测出来"，
但**理由不同**：0.3022 只比支持线高 0.0022（擦线），0.2569 则落在中间带的中部。

**问题二：`native_oracle_angle` 只在 61% 的 hard 状态上可算。**
native 提议方向同样要求"第一个位移 > 0.5 m 的点"，而 native 只走 ≤4 个基元步、
每步 0.25 m，**位移恰好等于 0.5 m 是众数**——实现用的是严格大于，于是这批状态被剔除。
可配对状态 **12757 / 20903 = 61.0%**，被剔除的 8146 个里位移中位数正是 0.50 m。
这个子集**不是随机子集**（偏向 native 走得更远的状态），它上面的 `ang>45` 是 0.3054，
比全集的 0.2795 高 2.6pt。判据读的是全集口径 **0.2795**。

预注册文本写的是"≥0.5 m"，实现写的是"> 0.5 m"，差别正好落在众数上——
**这是实现与预注册文本的偏离，记在这里，不回改判据。**

## 3. D3 — 一个判据失效，一个支持

### 3.1 D3a：`revisit_state_frac` 和 `episode_gap` 都测不出我想测的东西（判据设计缺陷）

`revisit_state_frac` 实测 **0.4506**（13887 / 30816），远高于 0.05 的支持线。
**但这个数不能读。** DAgger 采集是**配额制**：每个 episode 最多提交 hard 2 个、normal 1 个候选，
而候选正是按 `loop` / `avoidable_revisit` / `oscillation` 这些标签挑出来的。
所以 0.4506 测的是"**被挑出来的候选里有多少是重访型**"，
**不是"agent 有多大比例的时间处在重访状态"**——后者才是判据想要的量。

`episode_gap` 实测 **+0.99pt**（含重访状态的 episode 失败率 54.94%，不含的 53.95%），
远低于 +10pt 的支持线，但这个数同样不能反过来当"重访不影响成败"的证据：
**10804 个 episode 里有 8917 个（82.5%）至少含一个重访状态**，对照组只剩 1887 个 episode，
两组的差别已经不是"有没有重访"而是"这个 episode 短不短"。

判据是我写的，缺陷也是我的：预注册时没意识到 committed 候选自带选择偏差。
**按规矩判据不改**，D3a 记为**测量无效**，D3 的结论只由 D3b 承担。
想真正测重访发生率，需要的是**采集全轨迹的逐步位置**再统计，不是读候选池。

### 3.2 D3b：徘徊型失败在失败集里占四成 ✅

val_unseen 四个已完成评测臂，失败集（SR=0）里 `steps ≥ 3 × geodesic / 0.25` 的比例：

| 臂 | 失败数 | 徘徊型失败 | 占失败集 | 失败步数比中位数 | 徘徊∧超时 |
|---|---|---|---|---|---|
| native x11bundle v4 | 690 | 284 | **0.4116** | 2.52 | 117 |
| native seed1337 | 696 | 273 | **0.3922** | 2.33 | 119 |
| PPA v2 nativefix | 684 | 293 | **0.4284** | 2.54 | 129 |
| PPA v2 nativefix seed1337 | 714 | 293 | **0.4104** | 2.42 | 146 |

四个臂都在 0.39~0.43，支持线 0.15，**跨方法、跨种子一致**。
失败 episode 的步数中位数是测地距离的 **2.3~2.5 倍**——失败时 agent 通常不是"走一半停住"，
而是**走了远超需要的步数仍然没到**。占全部 episode 的比例是 14.8%~15.9%。

**但边界②必须一起读**：这是**超额步数代理**，不是重访的测量。评测 worker 只留
`progress.json` / `result.json`，**没有逐步位置轨迹**（`TrajectoryStepRecorder` 只在
DAgger 采集路径里启用），所以"走了很多步没到"里有多少真的是**重访/绕圈**、
多少是"沿着错误但不重复的路一直走"，本次**分不开**。0.41 是重访型失败的**上界**。

## 4. D2 — 未来头零样本方向准确率

判据：支持 = `Δ ≥ +10pt` **且** `top1_view_acc ≥ 0.50`；否定 = `Δ ≤ +2pt` **或** `top1_view_acc < 0.35`。

4000 个 hard 状态（四片各 1000，占全体 20903 的 19.1%），剔除 oracle 方向无定义/不可见的 234 个，
**实际计分 3766 个**；其中 native 侧可配对 2303 个（61.2%）。每片约 21 分钟。

| 量 | 值 |
|---|---|
| `future_head_top1_acc`（3766 个） | **0.7459** |
| `system2_top1_acc`（2303 个可配对） | **0.6791** |
| `future_head_top1_acc`（同一 2303 个） | **0.6765** |
| **`Δ = 未来头 − System2`** | **−0.26pt** |

**判定：❌ 否定**（`Δ = −0.26pt ≤ +2pt`，触发否定线；`top1_view_acc` 虽然过了 0.35/0.50，
但判据是"或"，任一触发即否定）。

**0.7459 这个数不是能力，是基线。** 未来头的预测分布是
**front 3743 / left 23 / right 0 / back 0**（99.39% / 0.61%）——它是一个**常数预测器**。
把它答对的 2809 个拆开：**2808 个来自"oracle 恰好也在前视"**，剩下 **1 个**来自 23 次 left 里蒙中的一次。
也就是说这个准确率**完全等于 oracle 的前视基线**（3766 个里 2829 个 oracle 在前视）。
System2 同样是常数"前"（§6③），所以这个"对照实验"实质上是**两个常数互比**：
Δ 在 8 个标签切片里有 **5 个精确等于 0.00pt**（另 2 个切片没有可配对样本，
唯一非零的 `avoidable_revisit` 是 −0.49pt，来自那 23 次 left）。

**在唯一需要它的地方，它是 0。** oracle 不在前视的 937 个状态里，未来头猜对 **1 个**
（预测分布 front 935 / left 2），准确率 **0.0011**；同一批上 System2 是 **0.0000**。

| 切片 | n | oracle 非前视 | 未来头 acc | 可配对 | System2 acc | Δpt |
|---|---|---|---|---|---|---|
| 全部计分 | 3766 | 0.249 | 0.7459 | 2303 | 0.6791 | −0.26 |
| `avoidable_revisit` | 2384 | 0.066 | 0.9266 | 1227 | 0.9120 | −0.49 |
| `loop` | 865 | 0.192 | 0.8046 | 518 | 0.8359 | 0.00 |
| `necessary_backtrack` | 737 | 0.650 | 0.3474 | 514 | 0.2802 | 0.00 |
| `off_route` | 928 | 0.683 | 0.3157 | 710 | 0.2986 | 0.00 |
| **`wrong_branch`** | 527 | 0.911 | **0.0873** | 424 | 0.0825 | 0.00 |
| **oracle 非前视** | 937 | 1.000 | **0.0011** | 739 | 0.0000 | +0.14 |

（**除第一行外都是事后切分**，与 §6 同属描述性，判定只用第一行。
读表注意两个口径："未来头 acc" 的分母是该切片的 n，"System2 acc" 与 Δ 的分母是其中的可配对子集。）

**这与 EXP-11 完全自洽。** EXP-11 读到未来标签 92.6% 落在前视、训练日志里未来侧/后视
Soft-IoU ≈ 0；D2 是同一件事的**行为学证据**：一个从未被训练过"往侧后指"的头，
零样本当然只会指前。**它不是"提议得不够准"，而是根本不发出可供门控的信号。**

**否定的方向对边界有利。** 边界③说 D2 用 Habitat 真值位姿会让**正面**结果成为上界；
反过来，**在最有利的位姿条件下拿到的否定结果更强**——换成部署期的 AMB3R VO 只会更差。
但边界④仍然成立：**这否定的是零样本**，不是"微调后也不行"。

内部一致性（与 D1 同源，可交叉核对）：剔除率 6.21% vs D1 的 6.18%；
可配对率 61.2% vs 61.0%；oracle 前视率 75.1% vs 74.3%。

## 5. 总门：预注册的决策表在这一格是空的

预注册的总门表只写了四行：`(支持,支持,支持)`、`(支持,支持,否定/没测出来)`、
`(D1 否定)`、`(D3 否定)`。实测是 `(D1 没测出来, D3 没测出来, D2 否定)`——**表里没有这一格**。
唯一能容纳 "D2 否定" 的第二行要求 D1 和 D3 都**支持**，前提不成立，所以那一行也用不上。

这是预注册的第二个缺陷（第一个是 §3.1 的选择偏差）：我写了三档判据，
却只为"全支持"和"任一否定"写了决定，没为"中间带"写。按字面读：

- 没有触发任何一条"停"的条件；
- 也没有满足任何一条"进实现"的条件。

所以**门控层面的结论是"没结论"**——它没有授权做决策层，也没有否掉它。
把"没测出来"读成"可以做"是事后放宽判据，不做。

但 D2 的否定是**有内容的否定**，它给下一步划掉了一条具体的路：
"拿现成的未来头当恢复提议器"**不成立**，因为那个头零样本只会输出常数"前"。
所以即便将来 D1/D3 被重新设计的判据判成支持，实现也**必须**从改训练目标起步
（DAgger 恢复状态微调 / 让未来头在离开专家轨迹的状态上有侧后监督），
不能从"加一层门控"起步——**没有信号可门控**。

下一步只能是**新的预注册**（EXP-13），靶子换成 §6 指出的那个。

四个结构性事实：

**① 原本设想的"重访否决"没有靶子。** 占 hard 状态 58.4% 的 `avoidable_revisit` 里，
native System2 的提议方向**已经有 92.1% 与 oracle 一致**，oracle 只有 6.4% 不在前视。
也就是说：**这些状态的失败不在决策层**——System2 知道该往哪走，问题在执行或更下游。
在这批状态上加一个"检测到重访就覆盖 System2"的模块，**九成以上的触发都是在改对的答案**。
D1 全集读数被稀释，主因就是这 58.4%。

这与 8 月 12 日那次 HCTF 免训练审计的判决**一致**，而那次判决此前没有进过台账。
产物 `model/hctf_training_free_v1/train_balanced_1024_native_pi0_seed42_final_v9/hctf_training_free_report.json`
（schema `hctf-training-free-audit-v6`，1024 个状态，场景不相交划分 42/8/9）里的 `decision` 段写着：

- `normal_history_veto_support: false`、`mode_aware_recovery_anchor_support: false`、
  `recovery_geometry_scene_disjoint_support: false`；
- `reason`: 匹配热力图**确实**含有场景不相交的候选特异安全信息
  （`matched_minus_shuffled_consistency` = **0.3006**，匹配 0.780 vs 打乱 0.479），
  "**但 normal veto 与 mode-aware recovery 策略都没能泛化到验证集**"；
- `native_candidate_support`: 28 个 native 坏环状态里，保守口径下只有 **6** 个存在 oracle 安全替代动作。

所以"重访否决"这条路**在两个互不相干的数据源上各被否了一次**：HCTF 用的是候选支持审计，
EXP-12 用的是 DAgger 状态几何。而 HCTF 当时给出的 `next_step` 恰好指向本次的结论——
"**当 native 样本没有安全替代时，补一个专门的恢复提议器**"——这条建议一直没有被执行。

**② 真正的靶子是 `wrong_branch` / `off_route`（5882 个，28.1%）。**
`wrong_branch` 上 oracle 有 **90.4%** 不在前视、中位夹角 **124.3°**（接近掉头）、
native 只有 **8.3%** 猜对。这才是"记忆本该起作用、而当前架构够不着"的状态。

**③ 两个"提议器"都是常数"前"。** native System2 侧：12757 个可配对 hard 状态里
方向分布是 `{front: 12756, left: 1}`，因为它输出的是**前视图里的像素目标**；
未来头侧（D2，§4）：3766 个计分状态里是 `{front: 3743, left: 23}`。
所以"System2 基线"其实是"永远回答前进"，准确率就等于 P(oracle 在前视)：
全体 hard 上 0.636、`wrong_branch` 上 0.083。
**D2 因此不是"新提议器 vs 聪明基线"，而是两个常数互比**——Δ ≈ 0 是结构决定的，
不是"未来头差一点"。要让任何一侧发出可门控的信号，都必须先改训练目标，不是改门控。

**④ 这把 EXP-11 的边界②从声明变成了测量。** EXP-11 读到"未来标签 92.6% 落在前视，
四方向对未来头只起统一坐标系的作用"，并已自行声明边界②"只在 R2R 专家轨迹上成立"。
本次给这条边界填上了数字：**同一个任务、同一批场景**，只要 agent 离开专家轨迹进入
`wrong_branch` 状态，未来分布就整个翻过来（90.4% 不在前视，中位角 124.3°）。
所以准确的说法不是"EXP-11 错了"，而是**四方向对未来头的价值取决于是否处在恢复状态**：
专家轨迹上冗余，恢复状态上必要。这句话要进论文，得由 EXP-13 预注册后重测。

## 7. 边界

预注册的五条边界全部保留，其中三条在本次实测后**变得更重要**：

① **DAgger 采集跑在 R2R train 场景、用 native 策略。** D1/D3a 描述的是
"native 策略在 train 场景遇到的恢复状态"，向 val_unseen 和当前方法的外推**未经验证**。
§6 的标签切分同样只在这个分布上成立。

② **D3b 的"徘徊"是超额步数代理，是重访型失败的上界**，不能反过来当重访率读（§3.2）。

③ D2 用 DAgger tar 里的 **Habitat 真值位姿**，不是部署时的 AMB3R VO；
已知位姿域偏移会把 pck8 从 0.88 压到 0.66，所以 **D2 的正面结果是上界**。
本次拿到的是**否定**，方向相反：在最有利的位姿条件下都不成立，换成 VO 只会更差，
所以这条边界**不削弱**本次的否定结论。
（补充证据：`src/config_schema.py` 里的守卫明确拒绝 "DAgger + PPA" 的训练组合——
"DAgger rows need a separate AMB3R cache before they may be enabled"。
本次探针**没有绕过这个守卫**，而是直接构造 `TrajectoryDaggerDataset` 只做前向；
守卫的存在本身就是边界③的佐证。）

④ D2 测的是**零样本**能力，否定不代表微调后也不行。

⑤ 三个诊断**都不测闭环 SR**，任何一条都不能作为 SR 主张的证据。

本次新增两条：

⑥ **D3a 无效**（§3.1）：候选池自带配额选择偏差，`revisit_state_frac` 与 `episode_gap`
都不能作为重访自然发生率或其危害的估计。

⑦ **§6 全部是事后切分**：它是 EXP-13 的假设来源，不是 EXP-12 的证据。
特别是"`wrong_branch` 上 native 只有 8.3% 正确"这个数**没有预注册的判据**，
不能直接写进论文当结论。

## 9. 这次实验自身的方法学教训

五条，都已写进台账 §5 的"反复踩过的坑"（第 11~15 条）：

1. **判据里凡是"占比"，先问分母是怎么来的。** D3a 的分母是一个**按目标标签筛出来的候选池**，
   于是"占比"必然高，与真实发生率无关。凡是从 DAgger 候选池算的比例，
   都只能横向比标签之间的相对结构，不能当绝对率。
2. **三档判据要配一张完整的决策表。** 只写"全支持怎么办""任一否定怎么办"，
   落到中间带就无据可依，事后怎么读都像在找补。
3. **几何指标要显式处理"未定义"这一档。** "第一个位移 ≥0.5 m 的点"在原地转向的状态上不存在，
   把它折进"不可见"会系统性地把未测量样本记成支持证据——本次正好发生在
   一个只差 0.0022 就跨过支持线的指标上。
4. **对照基线要先验一验它是不是常数。** D2 原本设计成"未来头 vs System2 提议"的配对比较，
   实测两边都是常数"前"，Δ ≈ 0 是结构决定的。**先打印一遍两侧的预测分布**，
   比事后解释 Δ 为什么是 0 便宜得多。
5. **拿配置起进程之前先 `ls -d` 一遍它引用的每个 `$VAR`。** 见台账 §5 第 11 条：
   漏导不会在启动时炸，而是在冷加载 20 分钟后炸。
