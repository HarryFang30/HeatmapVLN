# 实时性测试（任务 2）

**来源**：EXP-20 的 A0 种子 42 全量运行，开 `PPA_EVAL_TIMING=1`（09-30 已验证开计时不改变动作）。
**平台**：RTX 4090，模型服务端与里程计服务端各独占一张卡；客户端在同一台机器上跑 Habitat。
**样本**：全量 1839 集里 **24637 次带注入的规划调用**、96591 个执行动作。
**单位**：毫秒，报 n / 均值 / 中位数 / p90。明细 `exp20_a0_seed42_4090/runtime/20261001_015310_125250/latency/`。

> **仿真渲染单列。** 下表的 `simulator` 是 Habitat 的渲染与 `env.step`，真机上不存在；
> 评估真机节奏时要把它从总时间里去掉（见 §4）。

## 7. 真机上该怎么读这张表

- **一次规划约 5.26 s**（不含仿真渲染），**每个执行动作约 1.46 s**。
- 真机还要加上：相机实际曝光与传输、机器人执行 0.25 m / 15° 的时间、以及**机器人到服务端的网络往返**
  （这一项从未实测，见部署接口文档 §10）。
- **不要把这些数字搬到昇腾 910B 上。** 910B 的计时一个都还没做，台账 EXP-22 §1.3 明令
  「延迟数字一个都不许进台账」，那边的全部运行都是 `PPA_EVAL_TIMING=0`。

## 8. 边界

- 只在 4090、只在这一次运行（源码副本 `94146fa` 时期）、只在仿真图像上成立。
- 中位数之间不能相加成端到端（各阶段的中位数不发生在同一次调用）；要加总请用「合计」行或均值。
- 这是**单卡独占**的数：模型和里程计各自独占一张卡。多槽并发时每张卡仍是一套服务端，但主机侧会有争用。
