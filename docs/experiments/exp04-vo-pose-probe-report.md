# EXP-04 结果：VO 位姿域下"外观变重要"未被证实（种子间不稳定）

判据见 [台账 EXP-04](README.md#exp-04-位姿有噪声时外观是否变重要)（2026-09-03 预注册）。
提交物 [exp04-vo-pose-probe-submission.md](exp04-vo-pose-probe-submission.md)。

设置与 EXP-02 完全一致（同架构、同预算 12000 步、同两种子、契约 fail-closed 校验通过），
唯一变量是位姿来源：Habitat GT → **AMB3R VO 缓存**。

## 2. 判据判定：❌ 假设被否定

预注册："支持"= `full − pose-only` 的 pck8 差距在**两个种子上都 > 3pt**；
"否定"= 差距仍不稳定或 < 3pt。

实测 **+10.1pt（种子 42）/ +0.3pt（种子 1337）** ⇒ 种子间极不稳定 ⇒ **否定**。
"位姿不可靠时外观承担纠错"这句话**不能写进论文**。
（EXP-02 在 GT 位姿下的同一差距是 +6.8 / +0.1pt——同样不稳定，两个域一致地测不出这条。）

## 3. 描述性观察（非预注册，只能作现象记录）

1. **绝对水平整体下降**：full 的 pck8 从 GT 域的 0.88 掉到 VO 域的 0.66；
   位姿噪声直接决定了这个头的上限。
2. **位姿捷径在部署域明显变弱**：pose-only 从 GT 域的 0.848 掉到 0.564 / 0.647。
3. **图像在部署域变得更不可省**：涂黑图像在 GT 域只掉 8.7 / 12.6pt，
   在 VO 域掉 11.5 / 11.6pt，且**可见性 F1 直接塌到 0.000 / 0.373**（GT 域是 0.56 / 0.60）。
4. **vision-only 首次稳定高于地板**：+1.5 / +2.5pt（GT 域两者持平）。
5. 与 GT 域一致的部分：history-shuffle 无影响（槽位 k 的答案不用槽位 k 的图像）、
   pose-conflict 塌到地板而"位姿与目标同步滚"完全恢复 —— **定位仍由位姿驱动**。

## 4. 边界

1. 语料仍是 **random-walk**（`heatmap_randomwalk_train_v1`）配 randomwalk 的 AMB3R 缓存，
   不是部署评测的 R2R；只换了位姿来源这一个变量，因此可与 EXP-02 直接对照。
2. 仍是**从零初始化的 head-only 探针**、12000 步预算，不是部署权重（那是 EXP-03）。
3. 第 3 节全部是事后观察，**没有预注册判据**，不能当作论文主张，只能作为"为什么保留视觉支路"的说明。
