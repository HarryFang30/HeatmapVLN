## 3. 判据判定

### H1（parity + NE）：✅ 支持，但**擦边**

预注册要求三条同时成立：SR 与 SPL 的合并 95% CI 都含 0 且下界 > −1.5pt，且 NE 的 CI 上界 < 0。

| 条件 | 实测 | 判定 |
|---|---|---|
| SR CI 含 0 且下界 > −1.5 | 下界 **−1.4954** | ✅ 通过，但只比判据线高 **0.005pt** |
| SPL CI 含 0 且下界 > −1.5 | 下界 −1.4662 | ✅ |
| NE CI 上界 < 0 | 上界 **−0.0074** | ✅ |

**必须如实写明**：SR 那一条通过的余量是 0.005pt。换 6 个 bootstrap 种子（20000 次重采样）
下界稳定在 −1.4954，不是随机抖动；但如果当初把判据写成 −1.4pt，这条就是"没测出来"。
主表可以写"SR/SPL 与 native 持平、NE 显著改善（−0.11 m）"，**不能**写"SR 优于 native"。

### H2（长路径增益）：❌ 否定

预注册的否定条件是"种子 1337 的 ≥10 m 分层 SR 差 ≤ 0 或 NE 差 ≥ 0（方向翻转）"。
实测种子 1337 在 ≥10 m 上 SR **−0.92pt**（种子 42 是 +1.65pt）⇒ 方向翻转 ⇒ **长路径主张整体删除**，
并且预注册写死了"不换阈值重试"。合并后的 ≥10 m 分层 SR +0.37 [−1.65, +2.56] 也确实含 0。

intro 的"提升成功率与路径效率"因此**只能**改成"在不损失 SR/SPL 的前提下降低导航终点误差"。

## 4. 边界

1. 两个协议种子只改变 NextDiT 采样噪声，**不改变 System2 的贪心解码**；
   所以这里量化的是采样随机性，不是模型初始化或数据顺序的随机性。
2. NE 的 −0.11 m 是**统计显著但幅度很小**（native 4.11 m 的 2.6%），且 CI 上界只有 −0.007 m。
3. 只在 R2R val-unseen（11 个场景）上成立。
4. 两臂用不同的评测栈实现（桥臂 v3 修复栈、native 臂认证复刻栈），二者的 System2 前端已逐 token 对齐
   （EXP-01），但不是同一份代码；native 臂跑在锁定 checkout `HeatmapVLN_native_lock_bd5ead1` 上。
