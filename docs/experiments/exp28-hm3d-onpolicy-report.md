**诊断（只报，判定之后做的）.**

  所以问题不只在左转兜底：C1 学到的纠正转向整体上与指令无关。

## 结论

- **H-28 没有检验。** C1 在离线门被 kill，没有上 val，这条线这次不给 SR 读数。
- **线 B 的纠正信号确实被学进去了**（O4 +33pt，K1 也说明标签在几何上是对的）。但它们基本是"不看指令、按几何回到路线"的行为。
  - 这种行为在打乱指令下照样出现（O5）。
  - 它还把 ScaleVLN 专家路径上的决策带偏了（O1 −5.8pt）。
- 照预注册的家族规则，"HM3D 闭环 + 线 B DAgger"这一族到此停。

## 边界

- 结论只针对这套标签（线 B：几何 oracle、R4 的箭头规则、锚点 2×）与这个剂量（约 1 万个纠正、一遍）。
  - 不能推出"on-policy DAgger 本身无效"。
  - 也不能推出"HM3D 偏航状态没用"。
- O5 的近似拆分（按规则）只看了转向目标，像素目标没有重新判。
- 两处判据是看过结果后改的（N0 单边、AUD 参照）。
  - 它们都没有影响 kill：kill 来自 O5，而 O5 的线没动过。

## 下一步（待用户定）

1. **让纠正信号依赖语言。**
   - 只保留在打乱指令下底座与 oracle 答案不同的状态，也就是语言能区分的纠正。
   - 或者把 oracle 改成"沿指令描述的路线"而不是"回到参考路径"。
   - 这需要新预注册，O5 照旧作门。
2. **回到 val 失败的分解**，确认 MP3D 上错误的形态与 HM3D 偏航是否同类，再决定是否还投在 DAgger 上。

   - 所以这一轮没有自动开新实验。
