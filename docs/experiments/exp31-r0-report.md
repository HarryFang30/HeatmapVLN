# EXP-31 报告：R0，采样的 System2 能救回多少贪心失败的集

预注册见 `README.md` 的 EXP-31 节（判据 2026-10-20 04:20 UTC 写死，提交 `e515ec2`）。本文 2026-10-20 写成。

## 结果

- **集**：EXP-28 训练 cohort 里底座贪心（System1 种子 42）失败的 200 集（HM3D 训练场景，按种子 29 抽）。
- **两臂**：910B 底座无适配器，两臂 System1 都用种子 1337，标准协议；代码都是 `e515ec2`，含采样的 `top_k 0` 修正。
  - S：System2 采样（T 0.7、top_p 0.95）；
  - G：System2 贪心。

| | S（采样） | G（贪心，只换 System1 种子） | 差 S − G |
|---|---|---|---|
| 救回（成功） | **34.5%** | 23.5% | **+11.0pt**，95% 区间 [+3.3, +18.6]（按场景 bootstrap 20,000 次） |
| OS（进过 3 m） | 48.5% | 41.0% | +7.5pt |
| 步数耗尽 | 1% | 6% | −5pt |

- **判定：GO**（预注册线：差 ≥ +10pt 且区间下界 >0）。
- 有效性：
  - S 臂服务端日志有 "System2 SAMPLES (T=0.7 top_p=0.95)"，G 臂没有；
  - 两臂客户端与服务端同一提交；
  - 200 对全部配上；
  - G 臂 23.5% 与 10-14 取证时的自然救回率（约 22%）一致。

## 结论

- 在底座贪心失败的集上，整集采样 System2 比只换 System1 种子多救回约 11pt。
  - 这与 EXP-30 一致：正确的决策多半在 System2 的分布里，贪心取错了。
  - 这份多样性在闭环里能换成成功。
- 下一轮的方向因此有了依据：用闭环结局筛选自己的采样轨迹再训（RFT），或者训一个从样本里挑对的选择器。
  - 标签是模型自己在本集指令下的答案，按构造依赖语言，不会重蹈 EXP-28 的 O5 问题；
  - 也不违背底座的约定。

## 边界

- HM3D 训练场景、合成指令，只有一个温度，只有 200 集。
  - 区间宽（+3.3 ~ +18.6），+11 只是刚过 +10 的线。
- 这是在失败集上的救回率，不是全量 SR。
  - 采样也会把一部分本来贪心能成功的集弄坏：EXP-30 的对照里，首调用多数正确从贪心的 99.5% 降到 92%。
  - 所以"推理时直接采样"不等于提点，必须靠训练或选择把概率质量挪到对的那支上。
- 不能直接折成 val_unseen 的 SR；下一轮的候选仍要过离线门与两种子（最好四种子）配对 val，并统一用 sdpa。
