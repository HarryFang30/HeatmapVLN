# 真机部署与实验：从这里开始

这个目录交付的是**把导航模型接到真实机器人上**所需要的东西。
完整接口规格在 [`navigation_interface.md`](navigation_interface.md)（14 节）；本文是入口，
负责三件事：**你要做什么**、**已经验证到哪一步**、**哪些还没人验证过**。

> ⚠️ **到今天为止，这套系统没有在任何真实机器人上跑过。**
> 下面所有数字都来自仿真（Habitat R2R-CE）和 4090 上的服务端实测。
> 本目录是**接口交付**，不是真机实验报告。

---

## 1. 一句话接口

```python
agent = NavAgent(...)                       # 连到模型 / 里程计服务端
agent.reset(instruction)                    # 新任务
actions = agent.act(front_rgb, lookdown_rgb)  # 每次规划：最多 4 个离散动作
```

- **只要 RGB**，不要深度，也不要真值位姿 —— 位姿由里程计从 RGB 序列在线估计。
- **但不止一张图**：每次规划要**前视** + 一张**固定下倾 30°** 的图；
  慢系统在下视图上给像素目标，这是硬需求不是可选项。
- **输出**：停止 / 前进 0.25 m / 左转 15° / 右转 15°，外加下视动作。执行完这一块再重新规划。
- **前 20 步**里程计还在建图，这段只走原生路径，不用历史认知。

详见 [`navigation_interface.md`](navigation_interface.md) §3–§7。

## 2. 要准备什么

| 项 | 要求 | 来源 |
|---|---|---|
| 机器人 | 宇树 Go2 **EDU**（固件版本决定用哪版运动接口） | §14.1 |
| 相机 | **两台**：一台前视水平，一台固定下倾 30° | §13 |
| 算力 | 模型 + 里程计放在服务器（4090 一张 48 GB 卡放得下一套） | 本文 §4 |
| 网络 | 机器人到服务器；Go2 开发接口只支持有线，要另配无线或路由 | §14.2 |
| 代码 | Go2 一侧的程序由使用方按 §14 自己写；本仓库只交付接口与示意代码 | §13 |

## 3. 验证到哪一步了

**已经验证的，全部在仿真里：**

- `tests/test_nav_agent.py`（假服务端）：把 4090 金丝雀 4 集共 99 次规划调用的动作块喂回去，
  每次调用的步号、里程计帧号、历史帧号、地图版本号与部署日志**逐一相同**。
- `tests/test_nav_agent_habitat.py`（4090 容器）：同一组图像下，NavAgent 构造的请求与评测客户端的
  **逐字节相同**（JSON 逐字、JPEG 逐字节）；闭环 2 集时 124 个请求除仿真侧视图外全部逐字节相同。
- **真服务端逐调用比对**（2026-09-30，GPU 4）：4 集依次 14/14、30/30、28/28、27/27 次调用相同，
  每集结局相同，SPL / NE 与金丝雀**逐位相同**。

所以可以说的只有这一句：**NavAgent 接真服务端时，在那 4 集仿真上与部署的评测客户端逐调用相同。**

**完全没有验证过的（§10）：**

- 任何真实场景：真实图像、光照、运动模糊、动态障碍、执行误差、碰撞。
- **与仿真不同的相机**：仿真是离地 1.25 m、水平、HFOV 79°；
  Go2 自带相机估计只有约 **0.37 m** 高，视场也对不上。**这种视点从来没测过**，是最大的风险。
- 里程计在真实相机上的尺度与起步纯旋转时的稳定性。
- 超过 500 步的长任务；非英文或风格差别大的指令。
- **机器人到服务端的网络延迟和抖动** —— 下面的延迟预算里没有这一项。
- 金丝雀里没有 LOOK_DOWN，所以 LOOK_DOWN 相关路径只由假服务端闭环覆盖。

## 4. 延迟与显存预算

实测见 [`../experiments/exp20-latency-report.md`](../experiments/exp20-latency-report.md)（4090，24637 次规划调用）。

| | 中位数 |
|---|---:|
| 一次规划（不含仿真渲染） | **5.26 s** |
| 每个执行动作 | **1.46 s** |
| 其中 模型服务端 | 3.59 s |
| 其中 里程计（含建图更新） | 1.36 s |
| 每走一步送一帧进里程计 | 10 ms |

显存：模型约 **22.3 GB**、里程计约 **16.8 GB**（峰值保留），合计约 39 GB，
**一张 48 GB 卡放得下一套，24 GB 卡放不下。**

时间几乎全在慢系统上（两轮生成占模型服务端 47%）。**桥只占 1.4 ms（0.04%）。**

> 上表是**部署默认**的数。打开 `HEATMAPVLN_QWEN_VISION_MASK_PATCH=1`（Qwen2.5-VL 视觉窗口掩码补丁）后，
> 4090 上配对实测模型服务端 **3499 → 2744 ms**、一次规划 5108 → 4399 ms，4 集 99 次调用决定逐一相同
> （[`../experiments/exp20-latency-report.md`](../experiments/exp20-latency-report.md) §8）。
> 它**还不是默认**：全量 SR / SPL 是不带它跑出来的。
>
> 同一组 4 集上换 **flash-attention 2**（2.8.3.post1）更猛：模型服务端 **3499 → 1866 ms**、
> 一次规划 5108 → 3472 ms、每动作 1421 → 1017 ms，显存几乎不变。**2026-10-13 起这是 4090 的默认**
> （`PPA_EVAL_ATTN_IMPL`）。FA2 与 SDPA 的 bf16 数值不同，决定会变（4 集里相同前缀 1–11 次调用）；
> 用户定了两套数当同一套看。

⚠️ 真机还要加：相机曝光与传输、机器人执行 0.25 m / 15° 的时间、**网络往返**。前两项可估，第三项没测过。

## 5. 模型本身的证据

| 想知道 | 看哪里 |
|---|---|
| 完整模型在 R2R-CE val_unseen 上多少分 | [`../experiments/exp20-ablation-report.md`](../experiments/exp20-ablation-report.md)（SR 62.70，1839 集） |
| 去掉某个部件会掉多少 | 同上。**三个消融臂的配对 CI 都含 0，判定是「相当」** |
| 推理参数能不能降着省算力 | [`../experiments/exp21-sensitivity-report.md`](../experiments/exp21-sensitivity-report.md) |

**对真机部署最有用的一条**：S（采样条数）从 32 降到 1 只掉 1.8 pt、M（去噪步数）从 10 降到 2 只掉 2.8 pt；
但 **K（历史帧数）不能降**，降到 6 帧掉 5.8 pt、5 帧掉 6.2 pt。**省算力请从 S 和 M 下手。**

## 6. 上机之前必须定下来的

1. **相机型号、视场、分辨率、安装高度** —— 和仿真差多少，差了会怎样，没人知道。
2. **Go2 的型号与固件版本** —— 决定用哪一版运动接口。
3. **机器人到服务器的网络** —— 带宽、延迟、抖动，以及断线怎么办。
4. **离散动作够不够** —— 0.25 m / 15° 的步进，还是需要连续路点或速度指令。

第一次上机的建议顺序在 [`navigation_interface.md`](navigation_interface.md) §14.7，安全约束在 §14.6。
