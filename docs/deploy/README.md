# 实机部署：从这里开始

把导航模型接到宇树 Go2 上：模型跑在 4090 服务器上，狗背一台电脑跑机器人侧客户端 `NavAgent`，
通过网络调用服务器，把返回的离散动作变成 Go2 的运动。

> **到 2026-10-15 为止，这套系统没有在任何真机上跑过。**
> 下面的数字来自仿真（Habitat R2R-CE）和 4090 上的服务端实测；Go2 一侧只有在模拟狗上跑通过的示意代码。

完整说明在 [`navigation_interface.md`](navigation_interface.md)（下文的 §n 都指它）。

## 1. 全链路

```
4090 宿主机 · docker 容器 fjl-habitat · 一张 48 GB 卡
    模型服务端    :52400   指令 + 图像 → 动作块（最多 4 个动作）
    里程计服务端  :52500   RGB 序列 → 各帧相对位姿
        ▲
        │  gRPC（JSON + JPEG，无加密、无认证），走 ssh -L 隧道（§4）
        │  机器人侧电脑另配的无线网：Go2 的开发接口只有有线
        │
机器人侧电脑（x86 笔记本 / NUC，背在狗上，Python 3.10，一个进程）
    NavAgent  ·  两台相机的读取  ·  Go2 运动控制
        │                                   │
        │ 网线 192.168.123.x（DDS）          │ USB
        ▼                                   ▼
Go2 EDU 本体（192.168.123.161）         前视相机（水平）+ 下视相机（下倾 30°）
    收：速度指令 SportClient.Move
    发：位姿 rt/sportmodestate
```

## 2. 输入和输出

机器人侧只和一个对象打交道：

```python
from src.deploy import Action, NavAgent

agent = NavAgent("127.0.0.1:52400", "127.0.0.1:52500")            # 隧道后的模型服务端、里程计服务端
agent.reset(instruction, scene_id="go2lab", episode_id=run_id)    # 每集一次
while not agent.done:
    action = agent.act(front_rgb, lookdown_fn, level_fn)          # 每步一次，返回一个动作
    ...                                                           # 让 Go2 执行 action，停稳后拍下一帧
```

| | 什么时候 | 内容 |
|---|---|---|
| **输入** | 每集一次 | 英文指令；`scene_id`（字符串）、`episode_id`（非负整数），两者决定模型采样用的随机种子，每次实跑换一个 `episode_id` |
| **输入** | 每步一次 | `front_rgb`：上一个动作做完、停稳后在当前位姿拍的图。`numpy` 数组，`uint8`，形状 `(480, 640, 3)`，RGB。上一个动作是 `LOOK_DOWN` 时取下视相机，否则取前视相机 |
| **输入** | 只在要规划的那一步 | `lookdown_fn()`：返回下视相机（下倾 30°）的图，格式同上 |
| **输入** | 只在一种情况 | `level_fn()`：上一个动作是 `LOOK_DOWN`、且这一步取到动作块里的 STOP（表示"在这里重新规划"）时调，返回前视相机（水平）的图，格式同上 |
| **输出** | 每步一次 | 一个 `Action`：`FORWARD` 前进 0.25 m、`TURN_LEFT` / `TURN_RIGHT` 原地转 15°、`LOOK_DOWN` 车体不动（下一帧改取下视相机）、`STOP` 本集结束 |
| **异常** | 任何一步 | `act()` 抛任何异常，本集就作废：先让狗停下，再 `reset()` 开新的一集，不能在同一集里重试。`agent.done` 不会因异常变真 |
| **不需要** | — | 深度、里程计、定位、地图。相对位姿由服务器上的里程计从 RGB 序列在线估计 |

图像要求（水平视场 79°、垂直 63.5°、离地 1.25 m 等）、每个回调什么时候被调、一集里的调用顺序和诊断字段在 §2；
异常和超时在 §9。

## 3. 上机顺序

| 步 | 做什么 | 在哪 | 见 |
|---|---|---|---|
| 1 | 启动两个服务端，看到 `READY` | 4090 | §3 |
| 2 | 装环境，跑 `python -m pytest tests/test_nav_agent.py --noconftest -q`，应为 23 passed（不要 GPU、不要机器人、不要 torch） | 机器人侧电脑 | §5 |
| 3 | 开 ssh 隧道，构造一次 `NavAgent` 做连通自检 | 机器人侧电脑 | §4 |
| 4 | 只接相机、用假服务端跑通循环，狗不动 | 机器人侧电脑 | §7 |
| 5 | 不接模型，标定 0.25 m / 15° 的走法（方向、最小速度、容差、沉降时间） | Go2 | §6.4、§7 |
| 6 | 接真服务端：先只打印动作，再空旷房间低速实跑，有人拿遥控器跟着 | 全部 | §6.6、§7 |

## 4. 要准备什么

| 项 | 要求 | 见 |
|---|---|---|
| 机器人 | 宇树 Go2 **EDU**（AIR、PRO 不开放二次开发），固件 ≥ V1.1.6 | §6.1 |
| 相机 | **两台**，固定安装：一台前视水平、一台下倾 30°，尽量接近离地 1.25 m；去畸变后水平视场 ≥ 79°、垂直 ≥ 63.5°（16:9 的画面通常垂直不够） | §6.3 |
| 机器人侧电脑 | x86 Ubuntu 20.04 / 22.04，Python 3.10，有网口（接 Go2）和无线（连 4090） | §5、§6.2 |
| 服务器 | 4090 上一张没有别人进程的 48 GB 卡（两个服务端同卡约 40 GiB；24 GB 的卡放不下一套） | §3、§8 |
| 网络 | 机器人侧电脑能 ssh 到 4090 宿主机（地址和账号向负责人要） | §4 |

## 5. 延迟预算

4090 实测（R2R val_unseen 全量 1839 集、56236 次规划，两个服务端同卡）：

- 平均每 3.7 个动作规划一次。规划时机器人原地等（中位数）：用上历史帧和位姿的轨迹调用 **5.3 s**，
  预热期（前 20 帧）3.2 s，只跑慢系统的调用 2.5 s。这些数含两次取图（仿真里约 0.2 s，真机上换成读相机）。
- 摊到每个动作的计算约 **1.0 s**。
- 真机另加：Go2 走 0.25 m / 转 15° 再停稳的时间（§7 第 5 步实测）、网络往返（每步一次，每次规划再加两次）。

细分与带宽、显存见 §8。

## 6. 验证到哪一步了

**验证过的**：

- `NavAgent` 发出的请求与评测客户端（仿真里跑成绩用的 Habitat 客户端）逐字节相同（`tests/test_nav_agent_habitat.py`）。
- 接 4090 上的真服务端跑 4 集仿真，与部署的评测客户端逐调用相同（14/14、30/30、28/28、27/27 次调用），每集的结局和评测成绩都完全相同。
- `tests/test_nav_agent.py` 在 Python 3.10 上 23 个全部通过（2026-10-15）。
- §6.5 的 Go2 示意代码在按真实 SDK 签名写的模拟狗上跑通一集，取图路由、动作方向和三种故障处理都对（附录 C）。

**没验证过的**（附录 A），风险从大到小：

1. **相机视点**：仿真是离地 1.25 m、水平、HFOV 79°；装不到这个高度时，模型看到的是它从没见过的视角。
2. 真实图像、光照、运动模糊；动作执行误差；碰撞（模型完全不避障）。
3. 里程计在真实相机上的尺度，以及起步原地转圈时是否稳定。
4. 机器人到 4090 的网络延迟和抖动。
5. LOOK_DOWN 相关的路径只在假服务端闭环里测过（09-28 那 4 集里没有出现 LOOK_DOWN）。
